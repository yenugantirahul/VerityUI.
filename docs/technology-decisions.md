# Technology decisions

The selection follows the requirements and the local environment assessment. Node 24 is available on the workstation and is an LTS line. Playwright, the API, the CLI, and the review UI can share TypeScript contracts. PostgreSQL and the worker boundary allow the control plane and browser pool to scale independently. [Node release schedule](https://nodejs.org/en/about/previous-releases)

In the matrix, suitability includes functional and integration fit. Runtime covers performance and reliability, operations covers deployment and cost, and engineering covers security, maintainability, and ecosystem.

| Area and selection                                             | Suitability and integration                                                                                                                                                                                                  | Runtime and reliability                                                                                                                                    | Engineering and operations trade-offs                                                                                                                                                                                                                                                   |
| -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| React + Vite review UI                                         | Component-based evidence viewer with same-origin API and static assets. Vue + Vite is equally viable. Next.js adds SSR and server conventions that provide little for a signed-in review flow.                               | Client-side rendering keeps static deployment and request handling independent. Images load on demand.                                                     | React offers accessible control primitives and test tooling. Require native controls and keyboard coverage. One UI build without a second server runtime. [React](https://react.dev/learn/creating-a-react-app) · [Vite](https://vite.dev/guide/)                                       |
| Node 24 + TypeScript + Fastify 5                               | Shared Playwright and UI types with request schema validation. Python + FastAPI fits ML-first systems. Go is attractive for a high-throughput control plane.                                                                 | Async I/O and schema serialization suit control-plane workloads. Image CPU work belongs in the worker.                                                     | Fastify lifecycle, JSON schema, logging, and injection testing control service complexity. One runtime for the initial pipeline. [Fastify schemas](https://fastify.dev/docs/latest/Reference/Validation-and-Serialization/)                                                             |
| Playwright                                                     | Chromium, Firefox, WebKit, contexts, screenshots, masking, interception, and clock controls through one library. Puppeteer and Selenium can cover parts of the matrix with more capture orchestration.                       | One bounded context per job with explicit cleanup. Pin engine binaries and an OCI image.                                                                   | The image and library must match. Contexts preserve test isolation. The production browser requires OS and network isolation as well. [Playwright screenshots](https://playwright.dev/docs/screenshots) · [Docker](https://playwright.dev/docs/docker)                                  |
| PostgreSQL 18 + node-postgres + SQL migrations                 | Relational keys, transactional promotion, tenant-scoped queries, and row locks. SQLite is easy to ship and has a single-writer queue bottleneck. Prisma adds generation and still needs direct SQL for leases and promotion. | Transactional consistency and query tuning scale with indexed metadata. PostgreSQL 18 is supported and more established than the newly released major.     | Parameterized SQL and explicit transactions make locking and ownership reviewable. Separate runtime and migration identities in production. [Transactions](https://node-postgres.com/features/transactions) · [PostgreSQL RLS](https://www.postgresql.org/docs/18/ddl-rowsecurity.html) |
| PostgreSQL job table with leased claims                        | Atomically create runs and work in one transaction. pg-boss would provide richer queue semantics. BullMQ would introduce Redis and reconciliation.                                                                           | Short `SKIP LOCKED` transactions, heartbeat, claim token, bounded retries and stale lease recovery. Queue depth and DB pressure decide whether to migrate. | Maintain a small job state machine and test crash behavior. One durable service initial cost. [Row locking](https://www.postgresql.org/docs/18/sql-select.html)                                                                                                                         |
| pngjs + Pixelmatch                                             | PNG input/output and explicit perceptual pixel tolerance. Sharp/libvips can accelerate transforms. OpenCV adds structural operations and a native runtime.                                                                   | Predictable linear pixel work with bounded image dimensions. Benchmark wall time and RSS before choosing native acceleration.                              | Small dependency footprint. Pixelmatch supplies the pixel metric. Connected coarse tiles localize evidence with documented bounds. [Pixelmatch](https://github.com/mapbox/pixelmatch) · [pngjs](https://github.com/pngjs/pngjs)                                                         |
| Evidence rules followed by optional ONNX Runtime CPU           | Rules consume observed pixels and geometry. Evaluate frozen image embeddings and a calibrated classifier against rules. Hosted vision models need privacy approval and per-call budget. PyTorch suits research and training. | Rules are the fallback. CPU inference gets a time budget and runs outside authoritative comparison.                                                        | Version model, thresholds, features and evaluation data. Compare MobileNet-class and vision-language embeddings before selecting a model. CPU avoids a dedicated GPU bill. [ONNX Node binding](https://onnxruntime.ai/docs/get-started/with-javascript/node.html)                       |
| Content-addressed local disk and private S3 production adapter | Same immutable PNG contract via separate adapters. DB blobs couple image growth to database backups. A local volume is suitable for a single development machine.                                                            | SHA-256 verification and create-only writes support retries. Bucket lifecycle and private read policy scale by project volume.                             | Write bytes before committing metadata. Sweep unreferenced objects after a safe grace period. Scope keys and IAM to the deployment. [S3 conditional writes](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html)                                              |
| OIDC provider and application RBAC                             | Use authorization code + PKCE, server-managed sessions, and org membership roles. Local single-operator access for development. A bespoke password service would own recovery and MFA.                                       | Provider availability affects login. Existing sessions expire independently.                                                                               | HttpOnly Secure same-origin cookies, CSRF checks, and audited review. Provider and tenant policy require owner input. [OAuth security BCP](https://www.rfc-editor.org/info/rfc9700/)                                                                                                    |
| GitHub Actions and CLI first                                   | Portable CLI exit codes, JSON, and private artifact upload. GitHub App follows for check updates across PR lifecycle.                                                                                                        | Runner captures require a known browser image and scoped evidence.                                                                                         | Read-only CI permissions initially. Grant check writes to a restricted installation workflow after review. [GitHub Node CI](https://docs.github.com/en/actions/tutorials/build-and-test-code/nodejs)                                                                                    |
| OCI worker image and Docker Compose for local services         | API, worker, and Postgres can run separately. Managed containers or VMs meet early staging needs. Browser jobs exceed simple function runtime boundaries. Kubernetes is a later scale decision.                              | Keep browser, fonts, and runtime reproducible. Scale workers by queued capture count.                                                                      | Version image and dependencies together. Harden untrusted workers and restrict egress before staging. [Compose](https://docs.docker.com/compose/)                                                                                                                                       |
| Fastify structured logs, then OpenTelemetry                    | Correlate request and job IDs first. Export traces and metrics through OTLP as operations mature. Vendor-native collectors are a later procurement option.                                                                   | Bounded label cardinality and sampled traces to protect overhead.                                                                                          | Keep artifact URLs, headers, cookie state, and fixture values out of telemetry. [OpenTelemetry JS](https://opentelemetry.io/docs/languages/js/)                                                                                                                                         |
| Single npm repository + `tsc`                                  | One lockfile and incremental logical modules. npm workspaces, pnpm and Nx can help if independent package ownership or build bottlenecks appear.                                                                             | Build and type-check with `tsc`. Browser bundle uses Vite when introduced.                                                                                 | Exact direct dependency versions and `npm ci`. Few tools and documented Windows commands.                                                                                                                                                                                               |
| Node test runner, Fastify inject, Playwright                   | Node's runner covers unit and service tests with no additional runtime. Browser tests execute the actual built application. Vitest offers frontend mocking when the UI needs it.                                             | Use real browser processes, persistent storage and DB integration for behavior. Separate slow gates in CI.                                                 | ESLint and Prettier enforce static hygiene. Seeded fixtures make failures reproducible. [Node test runner](https://nodejs.org/api/test.html)                                                                                                                                            |

Initial versions are pinned in the package manifest and lockfile. Node 24.20.0, TypeScript 6.0.3, ESLint 10.15.0 and typescript-eslint 8.73.0 are compatible according to package engine and peer metadata. Playwright 1.64.1 is paired with the matching Noble image shown in its Docker documentation. React, Vite, PostgreSQL adapters and inference dependencies are installed when their phase begins. Foundation self-review checked priorities, trust boundaries, source of truth, failure handling, compatible tooling and gated dependencies against the brief.
