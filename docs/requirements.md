# Requirements

Deltaframe captures a known application state in a reproducible browser, compares it to an approved image, and lets a reviewer decide whether to promote the new image. Visual fidelity, data correctness, and CI decisions are distinct outputs.

| Priority | Functional scope                                                                                                                                                                                                                                                                      | Operational scope                                                                                                                                                                      |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P0       | Trusted local analytics fixture and Playwright capture for full pages and components. Baselines, PNG evidence, deterministic comparisons, asynchronous runs, project and suite configuration, review history, desktop and mobile viewports. CLI and CI feedback for trusted fixtures. | A loopback-only development environment, versioned migrations, immutable artifacts, validated inputs, bounded jobs, repeatable tests, and explicit review before promotion.            |
| P1       | Organization login, role-based project access, browser matrix, recurring runs, private artifact delivery, GitHub PR check updates, analytics assertions and an evaluated evidence assistant.                                                                                          | Authenticated tenant isolation, private object storage, isolated browser egress, sandboxing, retention, deployment automation, operational visibility, load and recovery verification. |
| P2       | Private-network runners, expanded device profiles, organization-wide policies, GitHub App installation flows, and analytics event validation as a separate extension.                                                                                                                 | Multi-region or dedicated pools where demand justifies them.                                                                                                                           |
| P3       | Train a model, use semantic embeddings or visual-language reasoning for novel categories, or add temporal comparison.                                                                                                                                                                 | Proceed when labeled evidence shows incremental diagnostic value and acceptable cost.                                                                                                  |

## Planning envelope

The sizing assumption is 10 teams, 5 projects per team, and 4 runs per project daily. At 12 captures per run, this gives 2,400 captures per day. At 400 KiB per screenshot plus 20% with three derived images of similar size, the rough upper planning estimate is 1.5 GiB/day or 45 GiB for 30 days. Approved versions and retained review evidence need separate lifecycle rules. Measure real compressed sizes, deduplication, failed jobs, and image egress before provisioning.

| Objective                 | Proposed initial target                                                                                                                                                                                                             |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| API control-plane latency | p95 under 250 ms at 10 requests/s for metadata operations in staging                                                                                                                                                                |
| Queue and worker latency  | p95 time to start under 30 s at planned load. p95 capture and diff under 15 s per fixture checkpoint.                                                                                                                               |
| Capture stability         | Byte-identical PNG output over 10 sequential captures per supported rendering profile for each deterministic reference case                                                                                                         |
| Resource envelope         | Start with 2 slots per worker and 12 million physical pixels per image. Benchmark RSS before increasing either.                                                                                                                     |
| Availability and recovery | 99.5% monthly API availability, 15-minute metadata RPO, and 2-hour RTO after tested restore                                                                                                                                         |
| AI acceptance             | Paired evaluation on held-out, grouped defects. Require no lost critical findings, improved macro-F1 by at least 0.05, p95 incremental latency under 2 s for local inference, and audited explanation faithfulness of at least 95%. |

Targets are acceptance hypotheses. Report measured values separately. Bound navigation, readiness, image size, cookie scope, retries, concurrent browser processes, response sizes, and retention. A browser context isolates state for trusted captures. Production hostile pages require a separate runtime and enforceable network policy.

## Assumptions and constraints

- Initial work targets Windows development and Linux CI. Baselines are scoped to exact browser and rendering profiles, including OS and worker image version. Cross-platform output equality is outside the capture guarantee.
- Initial browser execution is for operator-controlled fixtures or trusted configured targets. The service cannot accept arbitrary user-provided URLs until the worker egress and isolation gate passes.
- Screenshot artifacts may contain sensitive data. Production uses private storage, tenant-scoped access, short delivery lifetimes, redacted logs, and a documented retention policy. Storage state is passed from local secure configuration and excluded from version control.
- AI is optional and additive. It receives scoped evidence and emits schema-validated findings referencing known region IDs. Deterministic comparison, assertions, and required review continue independently.
- GitHub Actions is the first delivery integration. External deployment, paid services, identity provider, legal retention, data residency, and access to a GitHub organization require an owner decision before use.
